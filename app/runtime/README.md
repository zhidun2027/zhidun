# runtime (Live Hardening Run Directory)

This is the working directory (`user.dir`) the tool uses when it actually performs hardening. It already contains all the runtime resources needed for one complete hardening run, and it **has been verified on this machine** (see `samples/`).

## Directory Contents

| Item | Description |
|---|---|
| `config.dll` | Shell resource pack (generated by re-encrypting `config.dll.decrypted.zip` with the key `2025_09`; the decryption round-trip has been verified). The check is against the **file creation time + 540 days**; this file is newly created and valid long-term |
| `tools/apktool` + `apktool.jar` | The Linux build of apktool 2.10.0 (`apktool` is a wrapper script for `java -jar apktool.jar`). **On Windows, replace it with `apktool.bat`** |
| `tools/zipalign` | The Linux build of zipalign (from the Android SDK build-tools). **On Windows, replace it with `zipalign.exe`** |
| `tools/aapt2` | Needed when apktool uses `--use-aapt2` |
| `lib64/libc++.so` | Linux only: zipalign's shared-library dependency (`$ORIGIN/../lib64`). Not needed on Windows |
| `test.keystore` | Test signing keystore (alias `testalias`; both keystore and alias passwords are `111111`) |
| `samples/` | **Proof of a real run**: `original-clean.apk` → `hardened_clean_shell_sign.apk` |

## Run One Hardening Pass (Headless Command-Line Driver, for Verification)

```bash
# Launch from this directory (user.dir must be this directory; the tool looks here for config.dll and tools/)
cd runtime
java -cp "../build/libs/apk-jiagu-3.3.7-3.3.7-all.jar:<driver-classpath>" \
     com.frame.PackDriver  to-harden.apk  test.keystore
```

> Normal usage is to launch the GUI (`./gradlew run`): in the interface, choose the APK, choose the keystore, enter the password and alias, check the options, and click Start. The headless driver is only for automated verification.

## Hardening Pipeline (Verified Segment by Segment)

```
apktool d decompile  →  encrypt original DEX (weak stream cipher ^key^3-5)  →  generate cls_key
   →  extract config.dll shell contents (StubApp dex + libjiaguo.so ×4 ABIs)
   →  rewrite the AndroidManifest application to com.youyou.shell.StubApp
   →  apktool b repackage  →  zipalign 4-byte alignment  →  apksig re-sign (v1/v2/v3)
```

Verified contents of the output `hardened_clean_shell_sign.apk`:
- `classes.dex` = shell entry (contains `com/youyou/shell/StubApp`)
- `lib/{arm64-v8a,x86_64,mips64,armeabi-v7a}/libjiaguo.so` = native hardening engine
- `assets/<random-name>` = the encrypted original dex; `assets/cls_key` = shell key metadata
- Signatures v1/v2/v3 all pass verification

## How to Lay It Out on Windows

Lay out this directory (or any working directory) like this:
```
<working-directory>/
├── config.dll
└── tools/
    ├── apktool.bat        (the official apktool Windows batch file)
    ├── apktool.jar
    └── zipalign.exe       (from the Android SDK build-tools)
```
After you launch the tool, it looks for `config.dll` and `tools/` in `user.dir` or in the directory next to the selected APK. Sign with your own keystore.
